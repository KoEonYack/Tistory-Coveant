## 시작하며

<br />

좋은 글을 계속 발행했는데도 예전 글은 묻히고, 새 글만 홈 화면에서 잠깐 보이다 사라지는 사이트가 있습니다. 이런 문제는 개별 글의 제목보다 사이트 구조와 내부 링크에서 시작되는 경우가 많습니다.

<br />

검색엔진은 링크를 따라 새 페이지를 발견하고, 링크 문맥을 통해 연결된 페이지의 주제를 이해합니다. 독자도 마찬가지입니다. 다음 글로 자연스럽게 이동할 수 없다면 사이트에 좋은 자료가 많아도 찾기 어렵습니다.

<br />

이번 글에서는 카테고리, 태그, 허브 페이지, 내부 링크를 실제 콘텐츠 구조에 맞게 설계하는 방법을 정리합니다.

<br />
<br />
<br />

## 모든 중요한 페이지에는 들어오는 링크가 있어야 한다

<br />

사이트맵은 페이지 목록을 알려 주지만, 내부 링크를 대신하지는 않습니다. Google도 중요한 페이지는 사이트 안의 다른 페이지에서 적어도 한 번은 링크해야 한다고 안내합니다.

<br />

다음 구조는 단순하지만 충분히 강력합니다.

<br />

```text
홈
  └─ 주제 허브
       ├─ 입문 글
       ├─ 심화 글
       └─ 사례 / 도구 글

개별 글
  ├─ 이전 개념을 설명한 글
  ├─ 다음 단계의 글
  └─ 같은 질문을 다른 관점에서 다룬 글
```

<br />

새 글을 발행할 때 "홈에만 보이면 된다"고 생각하지 말고, 어떤 기존 글에서 이 글로 연결할지 함께 정하세요. 반대로 새 글에서도 독자가 먼저 읽어야 할 글과 다음에 읽을 글로 연결합니다.

<br />
<br />
<br />

## 앵커 텍스트는 링크의 설명문이다

<br />

`여기`, `더 보기`, `링크`만으로는 독자도 검색엔진도 다음 페이지의 내용을 알기 어렵습니다. 링크 텍스트만 읽어도 이동할 페이지를 예상할 수 있게 쓰는 편이 좋습니다.

<br />

```html
<!-- 좋지 않은 예 -->
<a href="/posts/robots-txt">자세히 보기</a>

<!-- 권장 -->
<a href="/posts/robots-txt">robots.txt와 noindex의 차이</a>
```

<br />

앵커 텍스트에 모든 키워드를 억지로 넣을 필요는 없습니다. 문장 안에서 자연스럽고 구체적으로 페이지를 설명하면 됩니다. 링크 앞뒤 문맥도 의미를 전달하므로, 관련 없는 링크를 한 줄에 몰아넣는 방식은 피하세요.

<br />

이미지를 링크로 사용할 때는 이미지의 `alt` 텍스트가 링크 설명 역할을 할 수 있습니다. 장식용 이미지에는 빈 `alt`를 두고, 실제 이동을 위한 이미지에는 목적을 알 수 있는 대체 텍스트를 사용합니다.

<br />
<br />

## 태그와 필터는 조합 폭발을 막아야 한다

<br />

태그 페이지와 필터 URL은 콘텐츠를 발견하게 하는 좋은 중간 계층이 될 수 있습니다. 하지만 지역, 날짜, 가격, 정렬, 상태 같은 조건을 모두 조합해 인덱스에 열어 두면 비슷한 페이지가 끝없이 늘어납니다.

<br />

다음 기준으로 나눠 보세요.

<br />

```text
색인 후보
사람이 실제로 찾는 주제다.
독립적인 제목, 소개, 충분한 항목이 있다.
다른 페이지와 명확히 구분된다.

색인 제외 후보
정렬 순서만 다르다.
결과가 거의 없거나 내용이 반복된다.
검색어, 로그인 상태, 임시 선택값에 따라 달라진다.
```

<br />

색인 제외 후보라고 해서 무조건 `robots.txt`로 막지는 않습니다. URL이 검색 결과에 나타나지 않아야 하는 경우에는 페이지가 크롤링 가능한 상태에서 `noindex`를 읽을 수 있어야 합니다. 이 원칙은 2부에서 다룬 robots.txt와 noindex의 역할 분리와 연결됩니다.

<br />
<br />
<br />

## 허브 페이지는 목록 이상의 역할을 한다

<br />

좋은 허브 페이지는 글 제목을 나열하는 곳이 아닙니다. 독자가 어느 글부터 읽어야 하는지, 각 글이 무엇을 해결하는지 알려 주는 안내판입니다.

<br />

예를 들어 SEO 시리즈 허브는 다음처럼 구성할 수 있습니다.

<br />

```text
SEO 기초
검색엔진이 URL을 발견하고 읽는 과정부터 정리한다.

기술 설정
sitemap, robots.txt, canonical, 렌더링, 구조화 데이터를 다룬다.

사용자 경험과 콘텐츠
속도, 콘텐츠 품질, 내부 링크 구조를 다룬다.

운영
Search Console로 변화를 측정하고 회귀를 막는 방법을 다룬다.
```

<br />

각 묶음에 짧은 소개를 두고, 글마다 어떤 질문에 답하는지 설명하세요. 독자는 필요한 글만 골라 읽을 수 있고, 검색엔진도 주제의 연결 관계를 파악하기 쉬워집니다.

<br />

허브의 소개 문구를 모든 태그 페이지에 복사하는 방식은 피해야 합니다. 각 허브가 다루는 주제와 포함된 콘텐츠가 실제로 달라야 합니다.

<br />
<br />

## 링크는 자동화하되 의미는 자동화하지 않는다

<br />

같은 카테고리 글을 자동으로 추천하는 기능은 유용할 수 있습니다. 다만 단순히 최근 글 다섯 개를 붙이는 것보다, 주제와 독자의 다음 질문을 기준으로 추천하는 편이 좋습니다.

<br />

```tsx
type RelatedPost = {
  title: string
  href: string
  reason: string
}

export function RelatedPosts({ posts }: { posts: RelatedPost[] }) {
  return (
    <nav aria-label="관련 글">
      <h2>이어서 읽기</h2>
      <ul>
        {posts.map((post) => (
          <li key={post.href}>
            <a href={post.href}>{post.title}</a>
            <span>{post.reason}</span>
          </li>
        ))}
      </ul>
    </nav>
  )
}
```

<br />

`reason`처럼 추천 이유를 같이 관리하면, 자동 추천이 문맥 없는 링크 목록으로 변하는 일을 줄일 수 있습니다. 관련성이 낮은 링크를 대량으로 붙이는 것보다 적은 수의 유용한 링크가 낫습니다.

## 정리

<br />

사이트 구조는 메뉴를 예쁘게 정리하는 일이 아니라, 독자와 검색엔진이 중요한 콘텐츠에 도달하게 만드는 설계입니다. 중요한 페이지에는 내부 링크를 만들고, 링크 텍스트는 이동할 페이지를 설명해야 합니다.

<br />

태그와 필터는 실제 수요가 있는 중간 계층으로 제한하세요. 그리고 허브 페이지에서는 글 목록뿐 아니라 읽는 순서와 각 글의 역할을 보여 주는 것이 좋습니다.
